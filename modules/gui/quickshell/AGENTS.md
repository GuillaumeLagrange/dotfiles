# quickshell bar

The session's status bar for niri, built on [quickshell](https://quickshell.org).
It started as a port of the eww bar (`modules/gui/eww/`), which is still
installed as a fallback but no longer autostarts.

## Layout

```
default.nix     The quickshell package (upstream flake input, not nixpkgs: it is
                newer and only the flake exposes `withModules`), the generated
                Config.qml, the assembled shell directory, and the user service.
qml/
  shell.qml     One Bar per entry in Quickshell.screens.
  Theme.qml     Singleton: gruvbox material palette, fonts, bar metrics.
  Config.qml    GENERATED by default.nix — absolute store paths, glyphs, and the
                glyph ink table.
  components/   Pill, PillGroup, Glyph, GlyphButton, Switch, Slider, Bubble +
                BubbleWindow (tooltip chrome), PopupPanel + HoverGate (hover
                panels), ClickPanel (click-driven, keyboard-capable panels),
                Tip (hover tooltip), TrayMenu + TrayMenuPanel (the tray's
                DBusMenu, drawn in QML).
  services/     Singletons: Niri (the IPC tap), Sys (cpu/mem/disk), Claude,
                Media (mpris), Quick (idle/dnd/power profile), Net
                (NetworkManager), Bt (BlueZ), Recorder (IPC in).
  bar/          Bar.qml plus one file per widget.
  popups/       NowPlaying, Calendar, QuickSettings, Networks, Bluetooth,
                Volume.
```

`niri-state` is shared with the eww bar: `default.nix` builds
`../eww/niri-state` and the QML reads its snapshot lines with a `SplitParser`.

## Running it

`quickshell.service` is wanted by `graphical-session.target`. It needs no
companion units: the power profile comes live from `Services.UPower`, dnd from
one `makoctl` query, and the idle lock is a held `Process`, so eww's
`settings-watch` and `idle-reset` units have no counterpart here.

```bash
systemctl --user restart quickshell
journalctl --user -u quickshell -e     # QML errors land here
qs -c bar                              # or run it in the foreground
```

## Design

**What the port deleted.** Everything eww needed a script for, quickshell has a
service for: `Services.Pipewire` (volume), `Services.UPower` (battery, power
profiles), `Services.Mpris` (media), `Services.SystemTray` (tray items and their
DBusMenu handles), `FileView` on procfs (cpu/memory). What survives as a process
is what genuinely is one: the niri tap, `df`, `claude-usage.sh`, `makoctl`, and
the held `systemd-inhibit` idle lock.

**Every popup is a speech bubble** (`components/Bubble.qml`): body and tail are
one closed `Shape` path, because the drawer background is translucent and a
separate triangle would double its alpha along the seam and draw the border
across the body. `BubbleWindow.qml` wraps it for tooltips, `PopupPanel.qml`
and `ClickPanel.qml` for panels.

**Two kinds of panel, both layer surfaces.** `PopupPanel` opens on hover and is
sized to its bubble, so the rest of the screen stays hoverable (media,
calendar, quick settings). `ClickPanel` opens on a click and covers the output,
so a click anywhere dismisses it - including on the bar, which a popup grab
does not report - and it can take `OnDemand` keyboard focus for the wifi
passphrase field (networks, bluetooth, volume). Controls inside either work:
the idle-inhibit switch really spawns `systemd-inhibit`, the media buttons
really pause the player. Tooltips stay `PopupWindow`s, which is all they need.

**The tray is an inline drawer, not a panel** (`bar/Tray.qml`): three dots that
widen into the applet icons while the pointer is on the pill. The icons live in
the bar window itself, so hovering into them never crosses a gap and no second
surface has to stay alive under the pointer.

**Panels are placed by the bar's geometry, not by the compositor.** The pill's
position is sampled with `mapToItem` when the panel opens, since mapping
functions are not reactive, and the bubble is placed at that x inside the
screen-sized window. That is also what makes the tail exact — nothing has to
guess how the compositor slid a popup that would not fit.

**Glyphs are centred on their ink** (`components/Glyph.qml`): nerd-font icons
have ascents, descents and side bearings that say nothing about where the shape
is drawn, so centring a `Text` centres the line box and every icon looks
nudged. `Pill` splits the leading glyph run out of its text and draws it
through `Glyph`, which covers script-fed pills (Claude, recorder) with nothing
per pill.

**`Networking` replaced nm-applet** (`services/Net.qml`, `popups/Networks.qml`):
the tray icon existed only to carry NM's state and its menu was the only way to
pick a network. `Networking.devices` gives the wifi and wired devices, a
`WifiDevice`'s `networks` the scan results, and each `Network` carries
`connect()` / `connectWithPsk()` / `disconnect()` / `forget()`. The scanner is
enabled only while the panel is open — the radio wakes for every sweep, and
without it a device lists its connected network alone.

**What nmcli still answers.** `Quickshell.Networking` models wifi and wired
devices only, and `NetworkDevice.address` is the hardware address, so three
things come from nmcli instead: VPN profiles (a WireGuard connection has no
`DeviceType` and never appears in `Networking.devices`), the IPv4/IPv6
addresses, and a saved profile's `connection.autoconnect`. One held
`nmcli monitor` drives the refresh, so there is no poll: NM only speaks when
something changed. Throughput comes from `/proc/net/dev`, sampled once a second
while the panel is open, and the public address from one `api.ipify.org`
request per open — nothing local can answer what the far end of a full-tunnel
VPN presents.

**`Bluetooth` replaced blueman-applet** (`services/Bt.qml`,
`popups/Bluetooth.qml`): `Bluetooth.defaultAdapter` carries the radio switch and
`discovering`, its `devices` carry `connect()` / `pair()` / `forget()`, the
`trusted` flag (which is what "connect automatically" means to BlueZ) and a
battery percentage when the device publishes one. BlueZ's freedesktop icon name
picks the row's glyph. Discovery is a button, not a side effect of opening the
panel: it is a radio duty cycle, it stutters A2DP, and the devices worth
connecting to are the paired ones, which are listed either way.

**Tray menus are drawn in QML** rather than handed to `QsMenuAnchor`, which
renders them as a `QMenu` and therefore needs `//@ pragma UseQApplication` — see
the gotcha below for why that is not an option here. `QsMenuOpener.children`
gives the entries (text, icon, enabled, separator, check state, `hasChildren`),
and a row's `triggered()` is the activation.

**The menu is one window covering the screen** (`TrayMenu.qml`), anchored to the
bar window's bottom-left corner. A window sized to the menu cannot be dismissed
by clicking the bar — see the grab gotcha — while this one gets every click,
and the ones that miss the menu close it.

**Submenus are pushed onto a `StackView`** of `TrayMenuPanel`s, replacing the
level on screen, which is the shape `caelestia-dots/shell` and
`DankMaterialShell` both use. A sideways flyout has to be reached by crossing
the rows between it and the pointer, and any of them takes the hover and closes
it. The stack is also what keeps each level's `QsMenuOpener` alive, which the
menu contents depend on (next gotcha), and a popped level is destroyed, so
`stack.clear()` on hide closes the menu for the application too.

**Config.qml is generated, for the same reason the eww yuck was**: every binary
is an absolute store path, and every nerd-font glyph is decoded in Nix from a
JSON `\u` escape (`glyph "F0493"`, surrogate pairs handled) so no QML source
carries a private-use character that an edit could silently strip.

**eww's hover machinery is two timers.** eww needed two runtime flag files and
an mtime comparison, because GTK fires hover-lost as the pointer crosses a
popup's child widgets; `HoverHandler` reports the whole subtree, so `HoverGate`
is a dwell timer plus a close debounce over "trigger or panel is hovered".

**The strip is drawn as siblings, not overlays.** The off-screen part of a
column is a scrim `Rectangle` with per-corner radii over the tile, rather than
eww's per-column CSS gradient; the rails are two 1px rectangles. Zero-width
spacers are free here — the `spacer` widget eww needed (a `:width 0` box is
still allocated a pixel in GTK) has no counterpart.

## Gotchas

- **A positioner's `implicitHeight` is read-only.** `Row`/`Column` compute it
  from their children, so children must not take their height from the row, and
  the row cannot be given one. Bar items size themselves from `Theme`.
- **In a `RowLayout`, a child whose implicit size depends on the layout's own
  size resolves to zero.** That is what emptied the left cluster: cells bound
  `implicitHeight` to the row, the row to the layout, the layout to the cells.
- **A panel of fill-width rows has no implicit width.** `ClickPanel.panelWidth`
  and `PopupPanel.minContentWidth` are the floor eww wrote as a CSS
  `min-width`; the content item must also `anchors.fill: parent`, or it keeps
  its own narrow implicit width inside a wider panel.
- **Qt measures some glyphs wrong.** `TextMetrics.tightBoundingRect` clamps a
  glyph's ink box to the baseline, so one drawn wholly above it (the tray's
  three dots) reports a box stretched down to the baseline and centres too
  high. `default.nix` reads the real outline bounds out of the font with
  fontTools for the ~2k glyphs where that happens, in em fractions, and
  `Glyph.qml` prefers them.
- **A layer surface that maps at 0x0 never gets pointer input**, even after it
  resizes: the empty input region is committed once. `PopupPanel` therefore
  takes its size from `implicitWidth`/`implicitHeight` (known before the show)
  and is placed with layer-shell margins, never from a four-edge anchor whose
  size only arrives with the compositor's configure.
- **`UPowerDevice.percentage` is a 0-1 fraction**, not 0-100 (`DBusDataTransform`
  multiplies the wire value by 0.01).
- **Filter `playerctld` out of `Mpris.players`** — it proxies whichever player is
  active, so the now-playing panel otherwise lists the same track twice.
- **Flakes only see git-tracked files.** A new QML file that is not `git add`-ed
  is missing from the assembled shell directory, and the bar fails to load with
  `Type X unavailable`.
- Singletons need `import QtQuick` for `Timer` and the `color` type; without it
  the whole shell fails to load with `color is not a type`.
- **`QsMenuAnchor` cannot be used here.** It needs `pragma UseQApplication`, and
  QApplication then loads the session's Qt *widget* theme plugins — stylix sets
  `QT_QPA_PLATFORMTHEME=qt5ct` and `QT_STYLE_OVERRIDE=kvantum`, built against
  nixpkgs' Qt while quickshell ships its own: kvantum fails to load on a
  `libQt6Svg` symbol and the shell then hangs before `Configuration Loaded`, so
  there is no bar at all. Menus are rendered in QML instead.
- **`PopupWindow.grabFocus` only reports clicks that miss the client.** The
  wayland popup grab dismisses the popup when the click lands outside it, but a
  click on another surface of the same client — any part of the bar — is
  delivered normally, so a popup sized to the menu stayed open (and the pill
  under the pointer reacted). Covering the screen with the menu window is what
  makes every click dismiss it.
- **Repointing a `QsMenuOpener` closes the menu it pointed at**, and an
  application then drops everything under it: giving one opener the submenu's
  handle made a submenu's entries arrive and immediately go back to zero. Every
  open level needs its own live opener, which is what the `StackView` holds.
- **A handler on an ancestor item is told about taps its children took.** The
  menu window's dismiss handler fires for clicks on the rows too, so it has to
  exclude the menu's own rectangle — and it has to do that on the *press*:
  entering a submenu resizes and moves the stack before the tap is reported,
  which put every click outside it and dismissed the menu that had just
  navigated.
- **A `Rectangle` takes no size from an anchor-filled child.** A row whose
  content is an `anchors.fill` `RowLayout` reports no implicit width, so the
  panel collapses to its minimum and every label elides; read the row's
  `implicitWidth` off the layout.
- **Do not redeclare `enabled` on an `Item`.** It shadows the built-in, and
  setting it false then also disables the handlers inside — a disabled menu row
  swallowed its own hover.
- **`QsWindow.itemRect()` is a call, not a binding.** Used in a property binding
  it keeps the geometry the bar happened to have when the binding first ran,
  which put the tray menu under the wrong pill; sample it when the menu opens.
- **`PopupAnchor.rect` is item-relative, and `relativeX` is deprecated.** With
  `anchor.item` set, `rect` carries the trigger's *size* (x and y are 0), so it
  cannot say where the popup ended up; anchor to `anchor.window` and set the
  rect yourself in `onAnchoring`.
- **A `ListView` hands an existing delegate the next model item.** The network
  list is rebuilt on every scan, so a row-local flag (the passphrase field was
  one) reappears against a different network. Per-item state belongs on the
  panel, keyed by the item.
- **A layer surface is the only way to type into the bar.** `PopupWindow` gets
  no keyboard focus, so the passphrase field lives in a `PanelWindow` with
  `WlrLayershell.keyboardFocus: OnDemand` — set on that window and not on the
  bar, or clicking any pill would take focus away from the focused app.
- **`Theme.alpha(c, 1.0)` is not a hover tint.** It rewrites the alpha, so a
  translucent white turned opaque white on hover and swallowed the label;
  `Qt.lighter` keeps the alpha.
- **A lookbehind regex silently matches nothing in QML's JS engine.**
  `line.split(/(?<!\\):/)` returned the whole line as one field, so the VPN list
  came out empty with no error; the terse parser is written out by hand.
- **`nmcli --terse` does not escape the colons of an IPv6 address**, only the
  ones inside other fields, so an address has to be rejoined from everything
  after the field name.
- **`Networking` populates on first access, not at startup.** A probe that read
  `Networking.devices` once, a few seconds in, saw zero devices; touching the
  service early and reading later sees them all.
- **Nerd-font icons are wider than their advance in the double-width Hack
  build**, so a glyph alone sits about a fifth of an em right of centre. The
  Propo build (`Theme.icon`) gives each glyph an advance matching its ink; use
  it wherever a Text holds nothing but glyphs.
- **A Text in a layout cannot shrink without `Layout.fillWidth`.** A row whose
  label was slightly too long pushed its trailing switch out of line with the
  row above — the layout overflowed rather than eliding.
- **A row's tap handler must sit on the row's header, not the row**, or it also
  takes the taps its own action buttons got and collapses the row out from
  under the click.

## Testing

niri has no cursor-warp action and the winit backend takes its size from its
host window, so the bar is exercised in a **nested niri inside a headless cage**
— off screen, at a fixed size, with a real niri IPC socket:

```bash
env -u WAYLAND_DISPLAY -u NIRI_SOCKET WLR_BACKENDS=headless \
  cage -- niri --config /tmp/nested-niri.kdl
```

The nested niri must **not** get `--session` (it would import its environment
into the session's systemd manager — see the repo `AGENTS.md`), and it only
exports `NIRI_SOCKET` to what it spawns itself, so the bar has to be launched
from inside it with `NIRI_SOCKET` pointed at `/run/user/…/niri.$WAYLAND_DISPLAY.*.sock`.
Screenshot with `grim` from inside that session.

The nested niri exposes `zwlr_virtual_pointer_v1`, so hover and click paths are
exercised for real. **`wlrctl pointer move` is relative**, so every hop has to
start from a known point: `move -5000 -5000` homes the cursor at the top-left,
and only the *first* `move` after it is a screen coordinate read off a
screenshot. Chaining two moves lands at the clamped bottom-right corner, which
looks exactly like a panel that ignores the pointer — it cost an afternoon of
chasing an input bug that did not exist.

```bash
W=wayland-N
WAYLAND_DISPLAY=$W wlrctl pointer move -5000 -5000   # home
WAYLAND_DISPLAY=$W wlrctl pointer move 618 671       # a tray icon
WAYLAND_DISPLAY=$W wlrctl pointer click right        # its menu
```

That is how tray menus, their submenus, panel dismissal and the controls inside
a panel are checked. Verify a control by its effect, not only by the pixels:
the idle-inhibit toggle really spawns `systemd-inhibit`, so `pgrep -af
systemd-inhibit` proves the click landed.
